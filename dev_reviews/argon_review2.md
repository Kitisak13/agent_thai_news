จากการตรวจสอบโค้ดฉบับปรับปรุงล่าสุด (`RSS_Code_with_MSTeam.gs`) เทียบกับบันทึกการแก้ไข (`dev_fix1.md`) และเอกสารโครงสร้างโปรเจกต์ (`README.md`) พบว่าทีมพัฒนาได้ยกระดับระบบขึ้นสู่ระดับ **Production-Grade** อย่างแท้จริง โค้ดมีความรัดกุม ปลอดภัย และแก้ปัญหาคอขวดเดิมได้ครบถ้วน

**คะแนนการประเมินรอบนี้: 9.7 / 10**

**สิ่งที่ทีม Dev ปรับปรุงได้ดีเยี่ยม (Highlights & Best Practices)**

- **ยกระดับความปลอดภัยและความเสถียรของระบบ:** การเพิ่ม `LockService.getScriptLock()` พร้อมบล็อก `try...finally` ป้องกันปัญหา Race Condition เมื่อทริกเกอร์รันชนกับการกดรันมือได้อย่างสมบูรณ์ และการเปลี่ยน URL ของ ScraperAPI เป็น `https://` ทั้งคีย์หลักและสำรองช่วยปิดช่องโหว่การส่ง API Key บนเครือข่ายได้อย่างถูกต้อง

- **การใช้ Structured Outputs (`responseSchema`) คู่กับ `gemini-2.0-flash`:** นอกจากการอัปเกรดเป็น `gemini-2.0-flash` และตั้ง `temperature: 0` แล้ว ทีม Dev ยังได้ใส่ `responseSchema` กำหนดชนิดข้อมูล (`INTEGER`, `STRING`, `enum`) บังคับโครงสร้าง JSON ใน `parseCandidatesWithGemini` ซึ่งช่วยการันตีว่า AI จะคืนค่า `ref_id`, `category`, และ `impact` ตรงตามฟอร์แมต 100% ไม่มีทางเกิด JSON พัง

- **ตัดวงจร AI Hallucination เรื่องวันที่อย่างเด็ดขาด:** การถอด `publish_date` ออกจาก Prompt และ Schema แล้วบังคับผูกเวลาจาก `pubDate` ของต้นทางผ่าน `ref_id` แทน ช่วยประหยัด Output Token และทำให้วันที่ในตารางแม่นยำ 100%

- **มีระบบ Time-box Guard ป้องกันสคริปต์ค้าง (6-Minute Timeout):** การเพิ่มตัวแปร `MAX_DOC_ITEMS_PER_RUN = 8` และเช็คเวลา `MAX_PROCESSING_TIME_MS = 4.5 * 60 * 1000` (4.5 นาที) เพื่อตัดจบการเขียน Google Doc แล้วรีบส่ง Email / MS Teams ก่อนที่ Google Apps Script จะตัดการทำงานถือเป็นการออกแบบเชิงป้องกัน (Defensive Programming) ที่ฉลาดมาก

- **แก้ไขบั๊กเดิมและจัดรูปแบบเอกสารใหม่ได้สวยงาม:** ลบเครื่องหมาย `\` ที่เคยติดในฟังก์ชันส่งอีเมลออกเรียบร้อยแล้ว และปรับดีไซน์การเขียน Google Doc (`appendNewsToDoc`) ให้ใช้ตาราง 1x1 ทำเป็นกรอบ Callout Box สีเทาอ่อน (`#F8F9FA`) สำหรับแสดงบทสรุป AI แยกออกจากเนื้อหาข่าวจริง ทำให้อ่านง่ายและเป็นมืออาชีพมาก

**จุดสังเกตและข้อเสนอแนะเพื่อพัฒนาต่อ (Recommendations for Phase 2 & 3)**

**1. การดึงรูปภาพประกอบและ Infographic หายไปจากโค้ดชุดปัจจุบัน (สอดคล้องกับแผน Phase 3)**

- **ข้อสังเกต:** ในโค้ดชุดล่าสุด ฟังก์ชัน `fetchFeaturedImage` และการส่งตัวแปรรูปภาพเข้า `appendNewsToDoc(doc, item, fullText)` ถูกถอดออกไปชั่วคราว ทำให้ตอนนี้ในรายงาน Google Doc มีเฉพาะข้อความล้วน ยังไม่มีภาพหน้าปกหรือกราฟแสดงผล

- **ข้อเสนอแนะ:** ในจังหวะที่ทีมเริ่มทำ **Phase 3 (Image & Infographic Pipeline)** แนะนำให้ผสานโค้ดแปลงแท็ก `<img>` ใน `cleanHtmlForAI` เป็น `[IMAGE_CANDIDATE: url | ALT: text]` เพื่อให้ `gemini-2.0-flash` คัดเลือกรูปกราฟ/อินโฟกราฟิกในเนื้อหาข่าวกลับมาพร้อมกับ `fullText` ในรอบการยิง API เดียวกัน แล้วดึงภาพผ่าน `wsrv.nl` (`&output=jpg`) เพื่อรองรับไฟล์ `.webp` ตามที่ได้วางแนวทางไว้ครับ

**2. แยกฟังก์ชันดึง HTML ออกจาก `fetchXml` เพื่อไม่ให้ URL ในหน้าเว็บเพี้ยน**

- **ข้อสังเกต:** ในบรรทัดที่ดึงเนื้อหาข่าวเต็ม (`htmlContent = fetchXml(item.url)`) ฟังก์ชัน `fetchXml` จะเรียก `sanitizeXmlEntities()` เสมอ ซึ่งแปลงเครื่องหมาย `&` ใน HTML ให้กลายเป็น `&amp;` ทั้งหมด

- **ผลกระทบ:** หากใน Phase 3 เราดึง URL ของรูปภาพจากใน HTML ที่มีพารามิเตอร์หลายตัว (เช่น `https://.../chart.jpg?width=800&quality=80`) URL จะกลายเป็น `&amp;quality=80` หรือในการดึงข้อความบางประเภทอาจติด `&amp;` ไปด้วย

- **ข้อเสนอแนะ:** ปรับพารามิเตอร์ของฟังก์ชันเป็น `fetchXml(url, isXml = true)` โดยถ้าส่ง `isXml = false` (เช่น ตอนดึงหน้าเว็บ HTML ของข่าว) ให้คืนค่า `response.getContentText()` ดิบๆ โดยไม่ต้องผ่าน `sanitizeXmlEntities` ครับ

**3. ใช้ `UrlFetchApp.fetchAll()` แทนการสร้าง Queue Sheet ที่ซับซ้อน (สำหรับ Phase 2)**

- **ข้อสังเกต:** ใน `dev_fix1.md` ระบุแผน Phase 2 ว่าจะทำ **Queue Sheet Architecture** เพื่อแก้ปัญหาข่าวเกิน 8 รายการ (`MAX_DOC_ITEMS_PER_RUN`) แล้วไม่ถูกบันทึกลง Google Doc เพราะกลัวติดลิมิต 6 นาที

- **ข้อเสนอแนะ:** การสร้างระบบ Queue Sheet อาจเพิ่มความซับซ้อนในการดูแลรักษาและเสี่ยงทำให้การส่งแจ้งเตือนล่าช้าไปอีกรอบรัน แนะนำให้ลองเปลี่ยนส่วนการดึงข่าวในขั้นตอนที่ 6 จาก `for` ลูปทีละข่าว มาเป็น **`UrlFetchApp.fetchAll()`** แทนครับ:

1. ยิง `fetchAll` ดึง HTML ของทุกข่าวพร้อมกันในครั้งเดียว (ใช้เวลา ~2-3 วินาที)
2. นำ HTML ทั้งหมดมาคลีน แล้วสร้าง Array ของ Requests เพื่อยิง `fetchAll` ไปหา Gemini API พร้อมกันทุกข่าว (เนื่องจาก `gemini-2.0-flash` รองรับ 15 RPM หากมีข่าวใหม่ 10-15 ข่าว สามารถยิงพร้อมกันในครั้งเดียวได้สบายโดยใช้เวลาเพียง ~4-5 วินาที)

3. วนลูปเขียนลง Google Doc อย่างเดียว

- วิธีนี้จะทำให้สกัดข่าวได้ถึง 12–15 ข่าวภายในเวลาไม่เกิน 30–40 วินาที โดยไม่ต้องจำกัดแค่ 8 ข่าว และไม่ต้องสร้างตาราง Queue เพิ่มเติมครับ

**4. ปรับปรุงเงื่อนไขการตรวจจับหัวข้อย่อย (Subheading) ใน `appendNewsToDoc**`

- **ข้อสังเกต:** ใน `appendNewsToDoc` มีการเช็คว่า `const isSubheading = (para.startsWith("**") && para.endsWith("**")) || ...` แล้วใช้ `.replace(/^[*#\s]+|[*#\s]+$/g, "")` ลบดอกจันออก แต่บางครั้ง Gemini อาจส่งหัวข้อย่อยที่มีดอกจันคั่นกลางหรือเน้นคำบางส่วนในย่อหน้าปกติ เช่น `**แนวโน้มราคาข้าว:** คาดว่าจะปรับตัวสูงขึ้น...` ซึ่งจะไม่เข้าเงื่อนไข `endsWith("**")` ทำให้มีเครื่องหมาย `**` โผล่ติดไปในเนื้อหา Google Doc ได้

- **ข้อเสนอแนะ:** แนะนำให้เพิ่ม `.replace(/\*\*/g, "")` ล้างเครื่องหมาย `**` ที่อาจหลงเหลืออยู่ในย่อหน้าปกติออกเสมอ เพื่อให้เนื้อหาใน Google Doc สะอาดตา 100% ครับ
