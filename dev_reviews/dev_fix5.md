## 1. ที่มาและปัญหาที่พบ (Root Causes)

จากการทดสอบดึงภาพ Infographic ในเนื้อหาข่าวจริง (เช่น ข่าวจากฐานเศรษฐกิจ) พบปัญหาว่าระบบไม่ดึงภาพอินโฟกราฟิกหรือภาพชาร์ตที่ฝังอยู่ในเนื้อหาข่าวลงใน Google Docs โดยมีสาเหตุสำคัญ 3 จุด:

1. **[Critical Filter Bug] ตัวกรองใน `cleanHtmlForAI` ตัดแท็ก `<img>` ที่มีแอตทริบิวต์ `loading="lazy"` ทิ้งทั้งหมด:**
   - โค้ดเดิมตรวจสอบ Regex กับทั้งแท็ก `imgTag`:
     ```javascript
     if (/avatar|logo|...|loading/i.test(imgTag)) return "";
     ```
   - เนื่องจากเว็บข่าวยุคใหม่ (รวมถึงฐานเศรษฐกิจ, กรุงเทพธุรกิจ, เครือมติชน ฯลฯ) กำหนดแอตทริบิวต์มาตรฐานของเบราว์เซอร์เป็น `loading="lazy"` ในแท็ก `<img>`
   - คำว่า `loading` จึงไปตรงกับแอตทริบิวต์ `loading="lazy"` ทำให้แท็กรูปข่าวทั้งหมดถูกลบทิ้งเป็น `""` กลายเป็นว่า Gemini ไม่เคยเห็น Marker `[IMAGE_CANDIDATE]` ของภาพข่าวเลย
2. **การตัดทอนข้อความที่ 45,000 ตัวอักษร (`substring(0, 45000)`):**
   - เว็บไซต์ข่าวมักมีโครงสร้าง JSON State (`__NEXT_DATA__`) หรือเมนูนำทางขนาดยักษ์อยู่ในช่วงต้นของโค้ด HTML ทำให้ข้อความช่วง 45,000 ตัวอักษรแรกยังไปไม่ถึงเนื้อหาข่าวช่วงกลางหรือท้ายบทความที่มีภาพ Infographic
3. **การบังคับดึง `og:image` (ภาพหน้าปก) มาใส่เป็นภาพแรกเสมอ:**
   - โค้ดเดิมใน `fetchArticleImages` จะควานหา `meta property="og:image"` มาใส่ในรายการภาพเสมอ ซึ่งภาพปกมักเป็นภาพ Stock Photo หรือภาพโรงงาน/ผู้บริหาร ไม่ใช่ชาร์ตหรืออินโฟกราฟิก ส่งผลให้มีภาพปกที่ไม่จำเป็นติดเข้ามาในเอกสาร

## 2. รายละเอียดการปรับปรุงในโค้ด (`RSS_Code_with_MSTeam.gs`)

### 2.1 แก้ไข `cleanHtmlForAI` ปลดล็อค `loading="lazy"` และขยายความจุข้อความ
1. **แยกการตรวจสอบ URL ออกจาก Attribute:**
   - สกัด `srcMatch` (ดึง URL จาก `src`, `data-src`, `data-original`, `data-lazy-src`) ก่อน
   - ทำการกรองไอคอน/โลโก้/แบนเนอร์/ตัวติดตาม **โดยตรวจสอบเฉพาะที่ตัว URL ของรูปภาพ (`imgUrl`)** เท่านั้น ไม่นำแท็ก HTML หรือแอตทริบิวต์มาตรวจ จึงไม่โดน `loading="lazy"` บล็อกอีกต่อไป
2. **สกัดพื้นที่เนื้อหาข่าวเป็นลำดับ:**
   - ค้นหาพื้นที่เฉพาะใน `<article>`, `<main>`, หรือ `<body>` ตามลำดับ เพื่อตัด Header/Footer/Nav Bar ส่วนเกินออกตั้งแต่ต้นทาง
3. **ขยายเพดานข้อความเป็น 80,000 ตัวอักษร:**
   - เพิ่มขนาดจากเดิม 45,000 ตัวอักษร เป็น 80,000 ตัวอักษร เพื่อให้ครอบคลุมเนื้อหาข่าวและรูปภาพกลางบทความทั้งหมด โดยไม่กระทบโควต้า Gemini 2.0 Flash

### 2.2 ปรับปรุง Prompt ใน `fetchFullContentWithGemini`
- อัปเดตคำสั่งใน `content_images`:
  - ขยายโควต้าภาพสูงสุดเป็น 4 ภาพต่อข่าว
  - ระบุชัดเจนให้ AI เลือกรูปภาพจาก `[IMAGE_CANDIDATE]` ที่อยู่ภายในเนื้อหาข่าว ทั้งภาพอินโฟกราฟิก แผนภูมิ ตารางสถิติ และภาพประกอบข่าวจริง
  - หากไม่มีภาพในเนื้อหา ให้คืนค่า Array ว่าง `[]`

### 2.3 ปรับปรุง `fetchArticleImages` ถอดภาพปก (`og:image`) ออก
- เอาการค้นหา `meta property="og:image"` ออก เพื่อให้ระบบดาวน์โหลดเฉพาะภาพประกอบและอินโฟกราฟิกในเนื้อหาข่าวที่ AI คัดเลือกมาจริงเท่านั้น
- คงระบบการแปลงภาพ `.webp` (รวมถึง URL ที่มี query parameters เช่น `?x-image-process=style/lg-webp`) เป็น `.jpg` ผ่าน Image Proxy (`wsrv.nl`) และการโหลดภาพแบบขนาน (`UrlFetchApp.fetchAll`)
